# Virtual Companion Telegram — текстовый MVP

Telegram-бот с оригинальным виртуальным персонажем Мирой. Ответы генерирует
Claude API. Персонаж честно обозначен как AI, помнит важное о каждом пользователе
отдельно, а расходы ограничены месячным бюджетом.

Архитектура, схема БД и планы: [docs/ARCHITECTURE.md](docs/ARCHITECTURE.md).

## Что умеет

* Естественная переписка на русском. Характер задаётся в [persona/mira.toml](persona/mira.toml).
* `/start` — приветствие, пометка «AI-персонаж, не реальный человек», подтверждение 18+.
* `/help`, `/privacy`, `/reset` (новый разговор, память сохраняется), `/memory`
  (что запомнено), `/forget` (стереть память или удалить все данные, с подтверждением).
* Память: история диалога, резюме прошлых разговоров, факты (как обращаться,
  интересы, предпочтения, незавершённые темы). Устаревшие факты заменяются.
  Всё хранится в PostgreSQL и переживает перезапуск.
* Индикатор «печатает…», разбиение длинных ответов, защита от повторной обработки
  апдейтов, лимиты частоты, понятные сообщения при сбоях API.

## 1. Что нужно подготовить (только вы)

1. **Токен бота.** В Telegram откройте [@BotFather](https://t.me/BotFather) → `/newbot` →
   скопируйте токен вида `123456789:AA...`.
2. **Ключ Claude API.** [console.anthropic.com](https://console.anthropic.com) → API Keys →
   Create Key. Пополните баланс. В разделе Limits можно задать лимит расходов
   и на стороне Anthropic — это вторая страховка к лимиту в боте.
3. **Где хранить секреты.** Только в файле `.env` на сервере (он в `.gitignore`) или в
   секретах хостинга. Не вставляйте токены в код, в git и в чаты.

```bash
cd companion
cp .env.example .env
chmod 600 .env
nano .env        # BOT_TOKEN, ANTHROPIC_API_KEY, POSTGRES_PASSWORD
```

## 2. Запуск через Docker (рекомендуется)

```bash
cd companion
docker compose up -d --build
docker compose logs -f bot          # ждите строку «bot @ваш_бот started»
```

Остановка: `docker compose down`. Данные лежат в volume `pgdata` и при этом
сохраняются. Удалить всё вместе с данными: `docker compose down -v`.

Резервная копия БД:
```bash
mkdir -p backups
docker compose exec -T db pg_dump -U companion companion | gzip > backups/$(date +%F).sql.gz
```

## 3. Локальный запуск без Docker

Нужны Python 3.12+ и PostgreSQL 14+.

```bash
cd companion
python3 -m venv .venv && . .venv/bin/activate
pip install -e ".[dev]"
createdb companion                    # или через psql: CREATE DATABASE companion;
set -a && . ./.env && set +a          # подгрузить переменные; добавьте в .env DATABASE_URL=postgresql://...
python -m companion
```

Миграции применяются автоматически при старте.

## 4. Тесты

Тесты не обращаются к настоящим Telegram и Claude: модель подменяется, а Bot API и
Anthropic API заменяются локальными HTTP-серверами. Нужен PostgreSQL.

```bash
cd companion
# один раз: отдельная пустая база только для тестов
psql -c "CREATE USER companion WITH PASSWORD 'companion' CREATEDB" && createdb -O companion companion_test
export TEST_DATABASE_URL=postgresql://companion:companion@localhost:5432/companion_test
python -m pytest -q
ruff check src tests scripts
```

⚠️ Тесты очищают базу `TEST_DATABASE_URL` (DROP SCHEMA). Не направляйте их на рабочую БД.

## 5. Первый живой запуск: проверка характера и Telegram

**Шаг 0 — проверка характера без Telegram (платно, < $0.01).** Скрипт отправляет 7 типовых
сценариев в настоящий Claude API и печатает ответы с простыми автоматическими проверками.
Ключ берётся из окружения:

```bash
cd companion
set -a && . ./.env && set +a
PYTHONPATH=src python scripts/live_check.py --yes
```

Оценивать ответы должен человек: автоматические проверки ловят только грубые ошибки
(пустой ответ, «Здравствуйте», не сказала, что она AI, и т. п.).

**Проверка в Telegram:**

1. Найдите бота и нажмите **Start**. Должно прийти приветствие с пометкой «AI-персонаж,
   не реальный человек» и кнопка «Мне есть 18, начнём».
2. Напишите «привет» до нажатия кнопки — бот попросит подтвердить возраст.
3. Нажмите кнопку и напишите: «меня зовут Саша, я люблю джаз, а завтра собеседование».
   Ответ должен быть коротким и живым. Ещё пара реплик — без нового «привет» в каждой.
4. Спросите «ты настоящая?» — она должна честно сказать, что она AI.
5. **Долгосрочная память.** Вызовите `/reset`, подождите 5–10 секунд (память сжимается в
   фоне) и откройте `/memory`: там должны появиться имя, интерес и тема про собеседование.
   Без `/reset` факты извлекаются автоматически примерно через 15 обменов сообщениями.
6. **Сброс диалога.** После `/reset` спросите «о чём мы только что говорили?». Дословной
   истории прошлого разговора у неё уже нет — это и есть сброс. При этом имя и факты из
   `/memory` она знает (спросите «как меня зовут?»).
7. **Перезапуск.** `docker compose restart bot`, затем «как меня зовут и что я люблю?» — факты
   и текущий диалог сохраняются в БД и переживают перезапуск.
8. **Удаление.** `/forget` → «Память и историю» → «Да, удалить» → `/memory` пуст, и на
   «как меня зовут?» она уже не знает ответа (кроме имени из профиля Telegram).
9. Отправьте стикер — бот ответит, что понимает только текст.
10. Расходы: `docker compose exec db psql -U companion -c "select date_trunc('day', created_at) d, operation, count(*), sum(cost_usd) from api_usage group by 1, 2 order by 1"`.

### Чем отличаются /reset, /memory и /forget

| Команда | Что делает | Что остаётся |
|---|---|---|
| `/reset` | Начинает новый разговор: прежние сообщения больше не попадают в контекст модели. Прежний диалог в фоне сжимается в резюме и факты | Факты, резюме, сама история в БД (для `/memory` и до срока хранения) |
| `/memory` | Показывает сохранённые факты, число резюме и сообщений. Ничего не меняет | Всё |
| `/forget` → «Память и историю» | Удаляет переписку, резюме и факты (после подтверждения). Если в этот момент идёт фоновое сжатие, удаление дожидается его и удаляет и его результат | Аккаунт и подтверждение 18+ |
| `/forget` → «Все мои данные» | Удаляет пользователя из БД целиком (после подтверждения) | Обезличенные суммы расходов в `api_usage` |

## 6. Модель, цены и лимиты

Проверено по официальной документации 2026-10-27:
[обзор моделей](https://platform.claude.com/docs/en/about-claude/models/overview),
[цены](https://platform.claude.com/docs/en/about-claude/pricing),
[кэширование](https://platform.claude.com/docs/en/build-with-claude/prompt-caching).
Перед запуском бот сам проверяет ключ и идентификаторы моделей через бесплатный
Models API: неверное имя модели или ключ — понятная ошибка при старте, без платных запросов.

| Модель (ID) | Вход | Выход | Чтение кэша | Запись кэша (5 мин) |
|---|---|---|---|---|
| `claude-haiku-5-5` — по умолчанию (промпт ≤ 100 000 токенов) | $0.10 | $0.50 | $0.01 | $0.125 |
| `claude-haiku-5-5` (промпт > 100 000 токенов) | $0.50 | $2.50 | $0.05 | $0.625 |
| `claude-sonnet-5-5` | $2 | $10 | $0.10 | $2.50 |

Цены в USD за 1M токенов, Claude API без `inference_geo`. Токены «размышлений» модели
оплачиваются как выходные и входят в `MAX_REPLY_TOKENS`. Бот ограничивает историю
16 000 символами, поэтому порог 100 000 токенов Haiku не достигается; тариф всё равно учтён
в расчётах. Промпт персонажа помечен для кэширования. Минимум для кэша у Haiku 5.5 —
512 токенов; промпт персонажа, по нашей оценке, больше. Сработал ли кэш, видно в
`api_usage.cache_read_tokens`.

| Оценка (не измерена на реальном трафике) | Стоимость |
|---|---|
| Одно сообщение (≈2–6 тыс. токенов контекста, до 1000 на ответ) | ≈ $0.0004–0.0011 |
| Фоновое сжатие памяти (примерно раз в 8 обменов) | ≈ $0.0005 |
| 1 000 сообщений | ≈ $0.5–1 |
| Бюджет по умолчанию $20/мес | ≈ 20–40 тыс. сообщений |

**Как работает лимит.** Расходы учитываются в USD за календарный месяц по UTC (таблица
`api_usage`). Перед каждым вызовом резервируется верхняя оценка его стоимости. Проверка
«потрачено + зарезервировано + оценка ≤ лимит» выполняется атомарно, поэтому одновременные
запросы не могут вместе превысить лимит. После ответа записывается фактическая стоимость
по `usage`. HTTP-ошибки API ничего не записывают: ответа с `usage` нет. Таймаут и отмена
(например, остановка бота во время генерации) записываются верхней оценкой с операцией
`*_unconfirmed`: ответ мог быть сгенерирован и оплачен. Учёт поэтому может немного
завышать расходы, но не занижает их. Резерв хранится в памяти процесса: запускайте бота
в одном экземпляре. Вторая страховка — лимит расходов в
[console.anthropic.com](https://console.anthropic.com) → Limits.

Ограничители (`.env`): `ANTHROPIC_MONTHLY_BUDGET_USD=20`, после 80% бюджета — переход на
`MEMORY_MODEL`, `PAID_APIS_DISABLED=1` — аварийное отключение всех платных вызовов (и ответов,
и памяти), `DAILY_MESSAGES_PER_USER=80`, `MESSAGES_PER_MINUTE=8`, `MAX_REPLY_TOKENS=1000`,
история ≤ 40 сообщений и 16 000 символов, `LLM_MAX_RETRIES=2` (только для 408/409/429/5xx и
сетевых сбоев; неверный ключ и 400 не повторяются), после 3 ошибок подряд пауза 60 секунд,
при неверном ключе — 10 минут.

### Известные ограничения

* **Маскирование данных** распознаёт только типовые форматы: карты (с проверкой Луна),
  телефоны РФ и международные, e-mail, IBAN, паспорт РФ, коды рядом со словами
  «код»/«cvv»/«pin», пароли после слов «пароль»/«password». Пароль или секрет без такой
  пометки («qwerty123» отдельным сообщением), адрес словами, номер в нестандартной записи
  **не распознаются** и сохранятся в истории. Модели памяти запрещено переносить такое в
  факты, но это инструкция, а не гарантия.
* В контекст попадают только 4 последних резюме. Подробности очень старых разговоров
  сохраняются лишь в виде фактов.
* Факты выделяет модель, она может ошибиться. Пользователь видит их в `/memory` и может стереть.
* Лимиты частоты и резерв бюджета живут в памяти процесса — один экземпляр бота.
* Живой диалог с настоящим Claude и Telegram в этой среде не проверялся (нет токенов).

Хостинг: самый маленький VPS (1 vCPU, 1 ГБ RAM) обходится примерно в $5–6 в месяц
(оценка, не проверялась).

## 7. Настройка персонажа

Отредактируйте [persona/mira.toml](persona/mira.toml): имя, возраст (не меньше 18),
биография, черты характера, вкусы, правила речи, примеры интонации и приветствие.
Перезапустите бота. Правила честности (AI-персонаж, не реальный человек, без выдуманных
событий) и безопасности заданы в коде (`CORE_RULES` в `src/companion/persona.py`) и
файлом персонажа не отключаются. Другой файл подключается через `PERSONA_PATH`.

## 8. Частые проблемы

| Симптом | Причина |
|---|---|
| `Ошибка конфигурации: Не заданы переменные окружения` | Не заполнен `.env` |
| `Telegram отклонил BOT_TOKEN` | Неверный токен — получите заново у @BotFather |
| `Anthropic отклонил ANTHROPIC_API_KEY` / `Модель … недоступна` при старте | Неверный ключ или `CHAT_MODEL`/`MEMORY_MODEL` |
| Бот отвечает «Сервис сейчас недоступен» | Ключ отозван или кончился баланс во время работы; в логах будет `llm configuration error` |
| `нет связи с Telegram Bot API` / `нет связи с базой данных` | Сеть до api.telegram.org или PostgreSQL недоступна; compose перезапустит бота |
| «Сервис временно приостановлен» | Достигнут `ANTHROPIC_MONTHLY_BUDGET_USD` или включён `PAID_APIS_DISABLED` |
| «Связь барахлит» | Временная перегрузка API; бот сам повторил запрос `LLM_MAX_RETRIES` раз |
| Бот молчит в группе | Так задумано: бот работает только в личных сообщениях |
