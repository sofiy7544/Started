# Этап 2. Архитектура и технический план

## Схема

```
 Telegram (iPhone) ── текст / (голос, файлы — этапы 5–6) / кнопки
        │
        ▼
 AccessMiddleware — белый список ALLOWED_TELEGRAM_IDS (до любой обработки)
 DedupMiddleware  — каждый update_id один раз
        │
        ▼
 Обработчики aiogram: меню и команды │ переписка
        │
        ▼
 Assistant (services/assistant.py) — не зависит от Telegram
   • лимит частоты, предохранитель после серии ошибок
   • разговор: последние MAX_HISTORY_TURNS обменов в пределах MAX_HISTORY_CHARS
   • инструкции: config/assistant.md + стиль + личные инструкции + дата
   • BudgetGuard: резерв верхней оценки → вызов → учёт фактической стоимости
        │
        ▼
 PydanticAIEngine (llm/engine.py) — единый интерфейс к моделям
   каталог config/models.toml: OpenAI │ Anthropic │ Ollama │ новые провайдеры
   ошибки провайдеров → понятные категории (FailureKind)
        │
        ▼
 SQLite (позже PostgreSQL) через SQLAlchemy 2 + миграции Alembic
```

## Memory Engine

| Уровень | Хранение | Как работает |
|---|---|---|
| Рабочая | `turns` текущего разговора | последние `MAX_HISTORY_TURNS` обменов в контексте |
| Долгосрочная | `memories`: preference, fact, project, agreement | извлекаются моделью каждые `MEMORY_BATCH_TURNS` обменов и при «Новом диалоге» |
| Процедурная | `memories` kind=procedure | «как владелец хочет выполнять задачи» |
| Эпизодическая | `episodes`: summary, decisions, open_items | что обсуждали, что решили, что осталось открытым |
| Семантическая | FTS5 (триграммы) по memories и episodes | поиск по словам и их формам; векторный поиск — с базой знаний (фаза 6) |

* Каждое воспоминание: тип, уверенность 0–1, важность 1–3, число упоминаний, даты создания,
  обновления и использования, источник (auto | user), статус (active | archived).
* **Дубликаты** объединяются (похожий текст и те же числа); **противоречия** — старое уходит в
  архив со ссылкой на новое (`superseded_by`); «забудь…» — в архив.
* В контекст ответа: до `MEMORY_CORE_ITEMS` главных (важность + уверенность + свежесть +
  упоминания) + найденные по текущему сообщению + похожие прошлые обсуждения. Блок помечен
  как данные, а не инструкции (защита от prompt injection).
* **Рост ограничен**: сверх `MEMORY_MAX_ACTIVE` в архив уходят наименее ценные.
* **Безопасность**: секреты, номера карт, документы, адреса не сохраняются (фильтр + запрет в
  инструкции); модель может трогать только id, которые ей показали, а запросы ограничены user_id;
  удаление ждёт фоновую обработку, чтобы удалённое не вернулось.
* **Управление**: «🧠 Память» — обзор, записи (исправить/удалить), поиск, экспорт JSON,
  очистка памяти, полное удаление всех данных; `/remember`.
* Стоимость: обработка 10 обменов моделью памяти ≈ $0.0002 (живой замер, gpt-6-luna).

## Voice Engine

```
голосовое / аудио / кружочек ─▶ скачать (до 20 МБ, до MAX_VOICE_SECONDS) ─▶ STT ─▶ «🎙 услышал…»
   ─▶ Assistant.ask ─▶ ответ ─▶ TTS (если режим голоса) ─▶ голосовое + текст подписью
```

* Движки: `STT_PROVIDER` = openai | local (faster-whisper), `TTS_PROVIDER` = openai | edge | none;
  `auto` — OpenAI при наличии ключа, иначе бесплатные. Новый движок — класс с методами
  `transcribe` / `synthesize` в `voice/providers.py`.
* Настройки владельца («🎙 Голос»): когда отвечать голосом (на голосовые / всегда / никогда), голос,
  скорость 0.9–1.3×, манера (естественно, спокойно, дружелюбно, энергично, по-деловому), пример.
* Естественность: текст перед озвучкой очищается от разметки, эмодзи и ссылок, пункты и абзацы
  становятся паузами; длинный ответ озвучивается до `MAX_TTS_CHARS` по границе предложения, полностью —
  текстом. Если озвучка не удалась, ответ приходит текстом.
* Деньги: распознавание — по точному usage, озвучка — оценка по длительности (`confirmed=false`);
  оба под тем же резервом бюджета, что и модели.
* Приватность: голос обрабатывается в памяти, на диск не пишется; в историю попадает распознанный текст.
* Чужое клонирование голоса не используется; обучение собственного голоса — фаза 9, только на ваших
  записях с согласия.

## Напоминания и инициатива

```
фраза ─▶ Assistant.ask ─▶ модель вызывает create/list/update/delete_reminder (только для этого
пользователя) ─▶ ReminderService (SQLite) ─▶ карточка подтверждения (по факту, не по словам модели)

цикл 15 с: claim_due ─▶ запись в reminder_deliveries (UNIQUE напоминание+время) ─▶ отправка
   ─▶ sent / повтор (до 5 попыток) / сдвиг расписания при постоянной ошибке
цикл 10 мин (отдельно): ProactiveService ─▶ правила ─▶ модель (повод из памяти) ─▶ отправка ─▶ журнал
```

* Время хранится в UTC, повторы (ежедневно, по будням, еженедельно, ежемесячно) считаются в
  часовом поясе пользователя — переход на летнее время не сдвигает напоминание.
* Перезапуск: расписание лежит в базе; пропущенное во время остановки приходит с пометкой
  «с опозданием», пропущенные повторы не копятся.
* Дубли: запись о доставке создаётся до отправки и уникальна, второй экземпляр бота не отправит то же.
* Инициатива: выключена по умолчанию; тихие часы; частота 72/24/8 ч со случайным сдвигом; не пишет,
  если пользователь писал последние 2 ч или не ответил на 2 сообщения; нужен повод (проект,
  договорённость, незакрытое дело), тема не повторяется 14 дней; при тратах ≥80 % бюджета — молчит.
* Исходящие сообщения сохраняются в историю, поэтому ответ «да, позвонил» бот понимает.

## Multimodal Processing Engine

```
фото / документ / видео / аудио / архив ─▶ Telegram File Handler (лимит 20 МБ, скачивание во временный файл)
   ─▶ safety: тип по содержимому, запрет программ и макро-форматов, zip-бомбы, XML-атаки, «бомбы» картинок
   ─▶ разбор в отдельном потоке с тайм-аутом:
        изображение → уменьшение до 2048 px, без EXIF/геометок
        PDF/DOCX/XLSX/PPTX/CSV/TXT/JSON/XML → текст локально (бесплатно), части по ~4000 символов
        скан PDF → страницы картинками для мультимодальной модели (OCR)
        видео → кадры по времени (PyAV, перемотка, не целиком в память) + речь по минутам (STT)
        аудио → речь по минутам (STT); ZIP → каждый файл отдельно, опасное — в отчёт
   ─▶ хранилище: текст по частям в базе, файлы на диске на MEDIA_RETENTION_HOURS (потом удаляются)

сборщик (bot/collector.py): сообщения подряд (альбом, файл + голосовое + текст) → одна задача
   ─▶ отчёт о получении (кодом, по фактам) ─▶ Context Manager ─▶ Assistant.ask(текст, вложения)
```

* **Context Manager** (`media/context.py`): новые вложения — прямо в запросе (картинки, текст целиком
  или начало и оглавление частей); все вложения разговора — в описи в инструкциях. Картинки в историю
  не сохраняются (пометка «вложение #N»), поэтому следующий вопрос не оплачивает их повторно.
* **Инструменты модели** (`media/tools.py`, только свои вложения текущего разговора): `view_attachment`
  (снова посмотреть фото/страницу/кадры), `read_attachment` (часть текста), `search_attachments`
  (поиск по всем текстам), `digest_document` (конспект всех частей дешёвой моделью, кэшируется),
  `video_frames` (кадры отрезка), `create_file` (xlsx, docx, csv, json, md, txt — собирает код).
* **AI Model Router** (`media/router.py`): текст документов — локально; речь — STT; изображения —
  выбранная модель, если видит картинки (`vision = true` в каталоге), иначе модель из `vision`;
  конспекты частей — дешёвая модель из `memory`.
* **Честность**: отчёт о получении строится кодом (что прочитано, что нет и почему); файл «создан» —
  только если инструмент сработал; модели велено писать, чего не хватило и насколько она уверена.
* **Расходы**: с вложениями резерв бюджета считается с запасом на шаги с инструментами; конспект частей —
  отдельной строкой `digest` в учёте.
* Ограничения: облачный Bot API отдаёт ботам файлы до 20 МБ; больше — только через свой сервер Bot API
  (`TELEGRAM_API_URL`, `MAX_FILE_MB`) — этот режим не проверялся. Интонация голоса не передаётся —
  модель получает распознанный текст.

## Безопасность (реализовано)

* Белый список Telegram ID; пустой список — бот не запускается. Посторонний не доходит до
  обработчиков и не тратит деньги; отказ — не чаще раза в час, попытка — в журнал.
* Секреты только в `.env` (в `.gitignore`); ошибки настройки не показывают значений.
* Логи: только типы исключений и места в коде (SafeFormatter), без текста переписки.
* Нет выполнения команд и доступа к файлам — инструменты появятся на этапе 7 с уровнями риска
  и обязательным подтверждением опасных действий.

## Расходы (реализовано)

* Месячный лимит `MONTHLY_BUDGET_USD` (USD, календарный месяц UTC), резерв до вызова атомарный —
  параллельные запросы не превысят лимит; потолок на запрос `PER_REQUEST_COST_LIMIT_USD`.
* Стоимость: из pydantic-ai/genai-prices; неизвестная модель — по максимальному тарифу.
* Таймаут/отмена/некорректный ответ — учёт по верхней оценке × число попыток.
* `PAID_APIS_DISABLED=1` — аварийное отключение платных моделей (локальная Ollama работает).
